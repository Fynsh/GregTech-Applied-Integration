# GregTech - Applied Integration

把 **GregTech CEu Modern（GTCEu）** 的机器/配方体系接入 **Applied Energistics 2（AE2）** 的 Forge 1.20.1 附属模组。

本模组以“矩阵多方块”为核心：玩家用 199 种矩阵方块搭建组装、电路组装、材料、流体材料四类结构，结构成型后通过框架端口接入 AE2 网络，并提供矩阵监控器、频道计数、核心/变压器规则与编码样板联动。

> 当前版本：`0.0.1`  
> 目标环境：Minecraft 1.20.1 / Forge 47.4.10 / GTCEu 7.5.3+ / AE2 15.4.11+

## 已实现功能

### 矩阵多方块

- 4 个族：
  - 组装矩阵（Assembly）
  - 电路组装矩阵（Circuit Assembly）
  - 材料矩阵（Material）
  - 流体材料矩阵（Fluid Material）
- 4 个外壳等级：基础、高级、精英、终极；
- 每族支持普通与超净框架/玻璃变体；
- 内部可放置：
  - 样板供应器核心（普通/扩展）；
  - 速度核心（普通/扩展，全部电压等级）；
  - 处理核心（普通/扩展，按族限定处理类型）；
  - 监控器核心（普通/扩展）；
  - 变压器与有源变压器；
  - 空核心、超净间、过滤器。

### 结构与监控器

- 结构尺寸可配置，默认 3..16（含外壳）；
- 结构必须是实心轴对齐长方体，内部不能有空气或无关方块；
- 恰好一个 GT 能源输入仓；
- 恰好一个矩阵监控器核心，且类型必须与外壳族一致；
- 框架/玻璃/能源仓/过滤器的位置限制；
- 成型详情保存到监控器 NBT：
  - 外壳类型与结构等级；
  - 有效矩阵等级 `matrix_level`；
  - 能源仓电压；
  - 样板供应器等价数量；
  - 速度核心、处理核心；
  - 变压器类型；
  - 超净间与过滤器信息。
- 监控器 BER 会把能源仓渲染成矩阵框架外观，并叠加 GT 能源仓 IO 标识。

### AE2 接入

- 只有矩阵框架方块注册 AE 节点宿主，玻璃等方块不能连 AE；
- 监控器侧创建频道节点，数量为：

  ```text
  1 + 所有样板供应器核心的等价数量
  ```

- 框架侧按面创建端口，一个框架可被多根线缆分别接入；
- 结构总频道数不是“每根线缆各算一份”，而是所有端口共享上面的 C；
- 频道节点按每个端口的实际容量分块连接，而不是所有节点连到所有端口；
- AE 实际链接的频道数会折算成“运行可用的样板供应器核心”；频道不足时矩阵本身保持
  连接，不会直接拒绝接入，超出部分的运行能力降级，但样板存储槽不缩减；
- 世界重进、结构重载、线缆后加载时会主动重扫/重连端口；
- 监控器数据在结构失效后默认保留 600 tick（30 秒），避免短暂破坏/退出重进丢数据。

### 矩阵样板 GUI

- 右击任意已成型矩阵的框架或玻璃打开样板页；
- 样板库存保存在监控器 NBT 中，关闭/重进/结构短暂失效不会丢失；
- 总容量 = `multiBlock.patternStorage.slotsPerProvider`（默认 9）× 监控器中已存储的
  等价样板供应器数量；该容量与 AE 当前链接的频道数无关，频道不足只影响后续运行能力；
- 界面显示 9×4 个可见槽位，超出部分用滚轮或右侧滚动条翻页；
- 每族仅接受同族编码样板：组装/电路组装/材料/流体材料；
- 支持玩家背包点击、Shift 快速移动、光标携带、从监控器取出、JEI 拖入；
- 监控器被破坏或数据保留期结束时，库存样板会掉落到监控器位置；
- 信息 GUI 第二页尚未实现，GUI 类中已预留 `initInformationPage` / `renderInformationPage` 空入口。

### 编码样板

- 新增四个自定义处理样板物品：

  | 类型 | 对应 GT 配方类型 |
  | --- | --- |
  | 组装编码样板 | 组装机 |
  | 电路组装编码样板 | 电路组装机 |
  | 材料编码样板 | 压模器、锻造锤、冲压机床、研磨机、车床、打包机、压缩机、线材轧机、卷板机 |
  | 流体材料编码样板 | 提取机、流体固化器 |

- 通过 JEI 的“编写样板”联动生成；
- 样板内部仍使用 AE2 原生处理样板 NBT 格式；
- 编码是服务端原子操作：输出槽为空、空白样板存在、快照合法、配方仍然存在，任一失败都不会消耗物品；
- 没有加入创造模式标签页或普通合成表，正常流程只能通过 JEI 编码获得。

## 搭建矩阵

### 基本形状

- 轴对齐实心长方体；
- 边长（含外壳）默认 3..16；
- 8 个顶点必须是矩阵框架；
- 棱只能是框架或能源仓；
- 普通表面可放框架、玻璃、能源仓、过滤器；
- 内部必须被核心/监控器/变压器/超净间等矩阵方块填满；
- 内部不能有空气。

### 必需方块

- **恰好 1 个 GT 能源输入仓**：
  - 注册名形如 `gtceu:<tier>_energy_input_hatch`、`_4a`、`_16a`；
  - 电压等级至少为 **HV**；
  - 低压（LV/MV）不会成型。
- **恰好 1 个矩阵监控器核心**：
  - 类型必须与外壳族一致；
  - 普通/扩展均可。
- 框架必须同族同等级；
- 玻璃若存在必须与框架同等级；
- 超净间最多 1 个。

### 核心与外壳匹配

- 样板供应器核心、速度核心、监控器核心：必须与外壳同族；
- 处理核心：按结构定义允许的处理类型匹配；
- 变压器：内部均可放置，不参与外壳类型匹配；
- 空核心：仅填充内部。

## 矩阵等级与电压规则

### 等级映射

| 结构等级 | 最高可用电压 |
| --- | --- |
| 基础 Basic | HV |
| 高级 Advanced | EV |
| 精英 Elite | IV |
| 终极 Ultimate | LuV |

监控器实际写入的矩阵等级：

```text
matrix_level = min(能源仓电压反映射等级, 结构自身等级)
```

例如：

- 精英结构（IV）+ HV 能源仓 → 有效矩阵等级为基础（HV）；
- 基础结构（HV）+ EV 能源仓 → 有效矩阵等级为基础（HV），能源仓过压。

NBT 中：

- `shell_level`：结构自身等级；
- `matrix_level`：写入监控器的有效矩阵等级。

### 核心过滤

写入监控器时：

- 电压高于 `matrix_level` 对应最高电压的速度核心/处理核心被忽略；
- 低于 HV 的核心不会因此被忽略，仍参与变压器链检查；
- 等于矩阵最高电压的核心不参与变压器链检查；
- 高于矩阵最高电压的核心只过滤，不爆炸。

### 能源仓过压

结构成型时：

- 能源仓电量 > 0，且能源仓电压 > 矩阵最高可用电压 → 能源仓爆炸；
- 能源仓电量为 0 → 不爆炸，但打上持久过压标记；
- 之后玩家给该能源仓接入电力，第一次检测到电量 > 0 时立即爆炸。

标记保存在监控器 NBT 的 `gtai_overvoltage_hatch`（能源仓位置），退出重进后仍然有效。

### 核心变压器链

结构成型时，若能源仓电量 > 0，对每个电压低于矩阵最高可用电压的速度/处理核心检查：

- **条件 A**：结构内含集成有源变压器；
- **条件 B**：含有从 `V_core` 到 `V_matrix - 1` 的连续电压等级变压器（每个等级至少一个）。

两个条件都不满足时，该核心爆炸。多个核心可同时爆炸。

## AE2 频道接入

- 结构总频道数：

  ```text
  C = 1 + Σ(样板供应器核心等价数量)
  ```

- 监控器创建 C 个普通频道节点；
- 框架只作为端口，不额外占用结构频道；
- 一个框架的多个面可以分别接不同线缆；
- 所有线缆的容量共同服务同一个结构；
- 玻璃不能连接 AE；
- 结构失效/重进时端口会重建，频道节点会重新接入；
- 重进世界后如果端口暂时没有拿到频道，会进行延迟重扫和恢复。

## 成型爆炸

### 能源仓过压

- 目标：能源仓；
- 条件：成型时电量为 0 则先标记；接电后立即爆炸；
- 成型时已有电量则立即爆炸。

### 核心缺少变压器链

- 目标：不满足条件的每个速度/处理核心；
- 条件：能源仓电量 > 0，且无有源变压器、也无完整连续升压链。

### 爆炸表现

- 播放爆炸音效与粒子；
- 不创建原版爆炸伤害；
- 不破坏其它方块；
- 不伤害/击退实体；
- 被摧毁的能源仓/核心按原方块掉落，物品 NBT 清空；
- 爆炸后结构会重新判定，通常会因缺少方块而失效。

## 编码样板与 JEI

### 使用方式

1. 安装 JEI；
2. 在 JEI 中查看受支持的 GT 配方；
3. 使用 JEI 的“编写样板”功能；
4. 输出对应类型的自定义编码样板；
5. 将样板放入 AE2 样板供应器/编码终端流程（实际矩阵执行器尚未实现）。

### 编码校验

- 输出槽必须为空；
- 必须有 AE2 空白样板；
- 输入/输出快照必须能组成合法处理样板；
- 配方在当前服务端配方表中必须仍然存在；
- 任一失败都不消耗空白样板，也不会覆盖输出槽。

## 配置

配置文件：`config/gtai-common.toml`

```toml
[multiBlock]
    minSize = 3
    maxSize = 16
    monitorDataRetentionTicks = 600

    [multiBlock.channels]
        base = 1
        perPatternProviderCore = 1

    [multiBlock.patternStorage]
        slotsPerProvider = 9

    [multiBlock.processingCore]
        extendedEquivalent = 2

    [multiBlock.patternProvider]
        extendedEquivalent = 2

    [multiBlock.speedCore]
        extendedEquivalent = 2
```

- `minSize` / `maxSize`：矩阵边长范围，含外壳；
- `monitorDataRetentionTicks`：结构失效后监控器数据保留时间，默认 600 tick；
- `channels.base` / `channels.perPatternProviderCore`：AE2 频道公式
  `base + perPatternProviderCore × 样板供应器等价数量`，默认值保持历史行为（1 + 数量）；
  运行可用核心数 = `(已链接频道 - base) / perPatternProviderCore`，不会超过结构中的等价数量；
- `patternStorage.slotsPerProvider`：每份等价样板供应器提供的样板槽数，默认 9；
  总容量 = 本值 × 监控器中存储的等价样板供应器数量；
- 三个 `extendedEquivalent`：扩展核心按几个普通核心计入数量/频道。

## 开发与构建

### 环境

- JDK 17；
- 使用仓库自带的 Gradle Wrapper；
- ForgeGradle 6；
- IntelliJ IDEA 或 Eclipse 均可。

### 常用命令

```bash
# Windows
gradlew.bat build
gradlew.bat runClient
gradlew.bat runServer

# Linux / macOS
./gradlew build
./gradlew runClient
./gradlew runServer
```

首次构建会下载 Minecraft/Forge/依赖，耗时较长。依赖缓存可用：

```bash
gradlew --refresh-dependencies
gradlew clean build
```

构建产物在：

```text
build/libs/gtai-0.0.1.jar
```

### IDE

IntelliJ IDEA：

1. 打开项目根目录；
2. 等待 Gradle 导入；
3. 确认 Project SDK 为 JDK 17；
4. 运行 `runClient` 或 `runServer` 配置。

### Jade 开发运行时

开发环境通过 `runtimeOnly` 加载 Jade：

```groovy
runtimeOnly fg.deobf("maven.modrinth:jade:${jade_version}")
```

- 仅用于开发环境实机查看方块/方块实体；
- 不参与编译；
- 不会打进模组 jar；
- 版本定义在 `gradle.properties` 的 `jade_version`。

## 已知限制

- 目前没有矩阵配方执行功能，不能把矩阵当作完整的自动合成机器；
- 样板供应器核心参与容量与频道计数，样板实际存储在监控器；尚未接入 AE 自动合成；
- 样板 GUI 目前只有样板页，信息页未实现；
- 监控器/框架的 AE 频道会在重进时重建，运行中的任务必须重新获取网络状态；
- 能源仓用于成型规则和过压检测，尚未接入运行时能量消耗；
- 编码样板依赖 JEI；
- 爆炸是自定义表现，不是原版爆炸实体，不会造成范围伤害。
