# GregTech - Applied Integration

把 **GregTech CEu Modern（GTCEu）** 的机器/配方体系接入 **Applied Energistics 2（AE2）** 的 Forge 1.20.1 附属模组。

本模组以“矩阵多方块”为核心：玩家使用 **199 种矩阵方块**搭建组装、电路组装、材料、流体材料四类结构，结构成型后通过框架端口接入 AE2 网络，并提供矩阵监控器、频道计数、核心/变压器规则、样板库存与信息 GUI。

整体行为参考 EAE 的合成矩阵：未来目标是让玩家把编码样板放入结构后，由矩阵高效执行对应配方，而不是依赖大量单方块机器逐一处理。**当前版本仍处于“结构 + AE2 接入 + 样板/GUI”阶段，配方执行器尚未实现。**

> 当前版本：`0.0.1`  
> 目标环境：Minecraft 1.20.1 / Forge 47.4.10 / GTCEu 7.5.3+ / AE2 15.4.11+  
> 仓库：<https://github.com/Fynsh/GregTech-Applied-Integration>

## 设计目标

1. 四类矩阵分别处理：
   - **组装矩阵**：组装机配方；
   - **电路组装矩阵**：电路组装机配方；
   - **材料矩阵**：压模器、锻造锤、冲压机床、研磨机、车床、打包机、压缩机、线材轧机、卷板机；
   - **流体材料矩阵**：提取机、流体固化器。
2. 矩阵不是 GT 多方块：使用本模组自己的扫描/验证逻辑，监控器方块实体保存状态；
3. 矩阵通过**矩阵框架**接入 AE2，玻璃不提供 AE 节点；
4. 矩阵内部使用样板供应器核心、处理核心、速度核心、变压器、超净间等方块表达运行能力；
5. 后续执行器将以监控器为控制中心，读取样板库存并执行对应 GT 配方。

## 矩阵方块与结构

### 199 个方块

| 类别 | 数量 |
| --- | ---: |
| 框架（4 族 × 4 等级 × 普通/超净） | 32 |
| 玻璃（4 等级 × 普通/超净） | 8 |
| 样板供应器核心（4 族 × 普通/扩展） | 8 |
| 处理核心（6 电压 × 7 处理类型 × 普通/扩展） | 84 |
| 速度核心（6 电压 × 4 族 × 普通/扩展） | 48 |
| 监控器核心（4 族 × 普通/扩展） | 8 |
| 变压器（LV..LuV） | 6 |
| 其它（超净间/过滤器/无菌过滤器/有源变压器/空核心） | 5 |
| **合计** | **199** |

资源校验任务会在 `check` 阶段逐项核对方块注册、模型、方块状态、战利品表、语言键与挖掘标签。

### 结构形状

- 轴对齐实心长方体；
- 边长（含外壳）默认 3..16，可在配置中调整；
- 8 个顶点必须是矩阵框架；
- 棱只允许框架或能源仓；
- 普通表面允许框架、玻璃、能源仓、过滤器；
- 内部必须被核心/监控器/变压器/超净间等矩阵方块填满；
- 内部不能有空气或无关方块。

### 必需方块

- **恰好 1 个 GT 能源输入仓**：
  - 注册名形如 `gtceu:<tier>_energy_input_hatch`、`_4a`、`_16a`；
  - 电压等级至少为 **HV**；
  - LV/MV 能源仓不会成型。
- **恰好 1 个矩阵监控器核心**：
  - 类型必须与外壳族一致；
  - 普通/扩展均可；信息页内容只对扩展监控器开放。
- 框架必须同族同等级；
- 玻璃若存在必须与框架同等级；
- 超净间最多 1 个。

### 核心与外壳匹配

- 样板供应器核心、速度核心、监控器核心：必须与外壳同族；
- 处理核心：按结构定义允许的处理类型匹配；
- 变压器、有源变压器：内部均可放置，不参与外壳类型匹配；
- 空核心：仅填充内部。

## 矩阵等级与电压规则

### 等级映射

| 结构等级 | 最高可用电压 |
| --- | --- |
| 基础 Basic | HV |
| 高级 Advanced | EV |
| 精英 Elite | IV |
| 终极 Ultimate | LuV |

监控器实际写入的矩阵等级：

```text
matrix_level = min(能源仓电压反映射等级, 结构自身等级)
```

例如：

- 精英结构（IV）+ HV 能源仓 → 有效矩阵等级为基础（HV）；
- 基础结构（HV）+ EV 能源仓 → 有效矩阵等级为基础（HV），能源仓过压。

NBT 中：

- `shell_level`：结构自身等级；
- `matrix_level`：写入监控器的有效矩阵等级。

### 核心过滤

写入监控器时：

- 电压高于 `matrix_level` 对应最高电压的速度核心/处理核心被忽略；
- 低于 HV 的核心不会因此被忽略，仍参与变压器链检查；
- 等于矩阵最高电压的核心不参与变压器链检查；
- 高于矩阵最高电压的核心只过滤，不爆炸。

### 能源仓过压

结构成型时：

- 能源仓电量 > 0，且能源仓电压 > 矩阵最高可用电压 → 能源仓爆炸；
- 能源仓电量为 0 → 不爆炸，但打上持久过压标记；
- 之后玩家给该能源仓接入电力，第一次检测到电量 > 0 时立即爆炸。

标记保存在监控器 NBT 的 `gtai_overvoltage_hatch`（能源仓位置），退出重进后仍然有效。

### 核心变压器链

结构成型时，若能源仓电量 > 0，对每个电压低于矩阵最高可用电压的速度/处理核心检查：

- **条件 A**：结构内含集成有源变压器；
- **条件 B**：含有从 `V_core` 到 `V_matrix - 1` 的连续电压等级变压器（每个等级至少一个）。

两个条件都不满足时，该核心爆炸。多个核心可同时爆炸。

## 成型爆炸

### 能源仓过压

- 目标：能源仓；
- 条件：成型时电量为 0 则先标记；接电后立即爆炸；成型时已有电量则立即爆炸。

### 核心缺少变压器链

- 目标：不满足条件的每个速度/处理核心；
- 条件：能源仓电量 > 0，且无有源变压器、也无完整连续升压链。

### 爆炸表现

- 播放爆炸音效与粒子；
- 不创建原版爆炸伤害；
- 不破坏其它方块；
- 不伤害/击退实体；
- 被摧毁的能源仓/核心按原方块掉落，物品 NBT 清空；
- 爆炸后结构会重新判定，通常会因缺少方块而失效。

## AE2 接入与频道

### 频道公式

结构总频道数：

```text
C = channels.base + channels.perPatternProviderCore × 样板供应器等价数量
```

默认配置为 `1 + 数量`。

- 监控器创建 C 个普通频道节点；
- 框架只作为端口，不额外占用结构频道；
- 一个框架的多个面可以分别接不同线缆；
- 所有线缆的容量共同服务同一个结构；
- 玻璃等非框架方块不能连接 AE；
- 结构失效/重进时端口会重建，频道节点会重新接入；
- 重进世界后如果端口暂时没有拿到频道，会进行延迟重扫和恢复。

### 实际频道判定

`linkedChannels` 不再只读 `IGridNode#getUsedChannels()` 的缓存值，而是统计：

```text
node != null && node.isActive()
```

`IGridNode#isActive()` 同时要求：

- 节点所在网络已通电；
- 网格已完成路径启动；
- 需要频道的节点确实拿到了频道。

因此：

- 未接线、框架端口为 0 → 未接入；
- 线缆离线/网络没电 → 未接入；
- 网络已通电但频道未分配 → 未接入；
- 只拿到部分频道 → 仍视为已接入，但信息页显示“频道不足”，可用样板供应器核心按实际链接数降级；
- 样板存储槽容量不随频道数缩减。

### 侧边栏与信息页状态

- 侧边栏显示 **AE 已接入（绿）/ 未接入（红）**；
- 信息页“可用”分区顶部显示：
  - `AE 网络：已接入 / 未接入`；
  - `频道使用：linked/required`；
  - `频道节点：N，框架端口：M`；
  - 频道不足时额外显示红色“频道不足”。

“已接入”以 `isAeNetworkOperational()` 为准：结构成型、初次校验完成、至少一个框架端口已接入，且需要频道时 `linkedChannels > 0`。

## 监控器数据

监控器方块实体使用根键 `gtai_multiblock` 保存结构详情，当前版本为 **v2**。

主要字段：

| 字段 | 说明 |
| --- | --- |
| `version` | 数据版本，当前 2 |
| `shell_type` | 外壳族：assembly / circuit_assembly / material / fluid_material |
| `shell_level` | 结构自身等级 |
| `matrix_level` | 有效矩阵等级 |
| `energy_voltage` | 能源仓电压片段，无法识别时省略 |
| `monitor_extended` | 是否扩展监控器 |
| `pattern_provider_count` | 样板供应器等价数量 |
| `speed_cores` | 速度核心：电压 + 等价数量 |
| `processing_cores` | 处理核心：处理类型 + 电压 + 等价数量 |
| `transformers` | 变压器类型（电压或有源） |
| `cleanroom` | 是否存在超净间 |
| `cleanroom_usable` | 写入阶段判定的超净间是否可用 |
| `filter_type` | none / cleanroom / sterile / mixed |
| `filter_count` | 过滤器方块总数 |
| `cleanroom_filter_count` | 超净过滤器数量 |
| `sterile_filter_count` | 无菌过滤器数量 |

超净间规则：

- 存在超净间且恰好只有一种过滤器 → 可用；
- 两种过滤器混用 → 类型 `mixed`，不可用；
- 没有过滤器 → 类型 `none`，不可用；
- 没有超净间 → 不写入过滤器数量，信息页该类目显示“空”。

兼容性：

- v1 只保存“有效”的过滤器类型与数量，混用/缺失会被折叠为 `none/0`；
- 载入 v1 数据时会按数量补算可用性；旧存档中已被折叠的混用数量无法还原。

结构失效后监控器数据默认保留 600 tick（30 秒），避免短暂破坏/退出重进丢失；期间样板库存仍保留，真正清理时掉落到监控器位置。

## 矩阵 GUI

### 样板页

- 右击任意已成型矩阵的框架或玻璃打开；
- 样板库存保存在监控器 NBT 中，关闭/重进/结构短暂失效不会丢失；
- 总容量：

  ```text
  slotsPerProvider（默认 9） × 监控器中已存储的等价样板供应器数量
  ```

  该容量与 AE 当前链接的频道数无关；频道不足只影响运行能力；
- 界面显示 9×4 个可见槽位，超出部分用滚轮或右侧滚动条翻页；
- 每族仅接受同族编码样板：组装/电路组装/材料/流体材料；
- 支持玩家背包点击、Shift 快速移动、光标携带、从监控器取出、JEI 拖入；
- 监控器被破坏或数据保留期结束时，库存样板会掉落到监控器位置。

### 信息页

- 左侧边栏宽 44px，显示“信息 / 样板”两个页签；鼠标点击或按 **Tab** 切换；
- 页签下方显示 AE 接入状态（绿=已接入，红=未接入）与“按 Tab / 切换页面”提示；
- 顶部固定标题“矩阵信息”，内容区独立滚动并带滚动条；
- 信息页**无玩家物品栏**：所有槽位通过 `Slot#isActive()` 隐藏，面板用代码按原版灰阶风格绘制；
- 信息页仅对**扩展矩阵监控器核心**开放内容；普通监控器只显示“请使用扩展……矩阵监控器”，页签仍保留；
- 分为“可用”（绿色）与“不可用”（红色）两个分区，分区随内容一起滚动；
- 固定类目顺序：
  1. 应用集成样板供应器核心
  2. 应用集成处理核心
  3. 应用集成速度核心
  4. 应用集成变压器
  5. 超净间（仅组装矩阵 / 电路组装矩阵）
- 处理核心显示“电压 + 处理类型 + 等价数量”，并预留运行状态扩展点；
- 变压器只显示类型（电压等级或有源），不显示数量；
- 超净间显示过滤器类型与数量。

“可用 / 不可用”判定只依据监控器数据：

- 类目为空 → 不可用分区显示“空”；
- 变压器电压等级既无速度核心也无处理核心 → 该变压器不可用；
- 存在有源变压器 → 其它变压器全部不可用，有源变压器可用；
- 速度核心缺少同电压处理核心 → 该速度核心不可用；
- 超净间以监控器写入的 `cleanroom_usable` 为准；
- 样板供应器因频道不足过载 → 过载部分列入不可用，只显示过载数量；
- 同一条目不会同时出现在两个分区。

样板槽使用情况：

- 可用容量 = 实际可用样板供应器数量 × 每核心槽数，不含被过载的供应器；
- 已用数量按可用容量封顶，使用率不超过 100%；
- 容量为 0 时显示 `0/0，—`。

## 编码样板与 JEI

新增四个自定义处理样板物品：

| 类型 | 对应 GT 配方类型 |
| --- | --- |
| 组装编码样板 | 组装机 |
| 电路组装编码样板 | 电路组装机 |
| 材料编码样板 | 压模器、锻造锤、冲压机床、研磨机、车床、打包机、压缩机、线材轧机、卷板机 |

- 样板内部仍使用 AE2 原生处理样板 NBT 格式；

- 没有加入创造模式标签页或普通合成表，正常流程只能通过 JEI 编码获得。

```toml
    [multiBlock.channels]
        base = 1
        perPatternProviderCore = 1

    [multiBlock.patternStorage]
        slotsPerProvider = 9

    [multiBlock.processingCore]
        extendedEquivalent = 2

    [multiBlock.patternProvider]
        extendedEquivalent = 2

    [multiBlock.speedCore]
        extendedEquivalent = 2
```

- `minSize` / `maxSize`：矩阵边长范围，含外壳；
- `monitorDataRetentionTicks`：结构失效后监控器数据保留时间，默认 600 tick；
- `channels.base` / `channels.perPatternProviderCore`：AE2 频道公式
  `base + perPatternProviderCore × 样板供应器等价数量`；
  运行可用核心数 = `(已链接频道 - base) / perPatternProviderCore`，不会超过结构中的等价数量；
- `patternStorage.slotsPerProvider`：每份等价样板供应器提供的样板槽数，默认 9；
- 三个 `extendedEquivalent`：扩展核心按几个普通核心计入数量/频道。

## 开发与构建

### 环境

- JDK 17；
- 使用仓库自带的 Gradle Wrapper；
- ForgeGradle 6；
- IntelliJ IDEA 或 Eclipse 均可。

### 常用命令

```bash
# Windows
gradlew.bat build
gradlew.bat runClient
gradlew.bat runServer

# Linux / macOS
./gradlew build
./gradlew runClient
./gradlew runServer
```

首次构建会下载 Minecraft/Forge/依赖，耗时较长。依赖缓存可用：

```bash
gradlew --refresh-dependencies
gradlew clean build
```

构建会执行 `verifyMatrixAssets`，校验：

- 199 个矩阵方块与 `方块注册映射.txt` / `MatrixBlocks.java` 一致；
- blockstate、block model、item model、战利品表、语言键、pickaxe 标签齐全；
- 4 种编码样板的模型、贴图与语言键齐全。

构建产物：

```text
build/libs/gtai-0.0.1.jar
```

### IDE

IntelliJ IDEA：

1. 打开项目根目录；
2. 等待 Gradle 导入；
3. 确认 Project SDK 为 JDK 17；
4. 运行 `runClient` 或 `runServer` 配置。

### Jade 开发运行时

开发环境通过 `runtimeOnly` 加载 Jade：

```groovy
runtimeOnly fg.deobf("maven.modrinth:jade:${jade_version}")
```

- 仅用于开发环境实机查看方块/方块实体；
- 不参与编译；
- 不会打进模组 jar；
- 版本定义在 `gradle.properties` 的 `jade_version`。

## 已知限制

- 目前没有矩阵配方执行功能，不能把矩阵当作完整的自动合成机器；
- 样板供应器核心参与容量与频道计数，样板实际存储在监控器；尚未接入 AE 自动合成；
- 信息页目前只展示监控器快照与 AE 频道状态，尚未展示运行中的任务与能量状态；
- 监控器/框架的 AE 频道会在重进时重建，运行中的任务必须重新获取网络状态；
- 能源仓用于成型规则和过压检测，尚未接入运行时能量消耗；
- 超净间状态已写入监控器，但执行器尚未消费；
- 编码样板依赖 JEI；
- 爆炸是自定义表现，不是原版爆炸实体，不会造成范围伤害；
- v1 监控器数据中混用过滤器的数量已被折叠为 `none/0`，无法恢复原始数量。
